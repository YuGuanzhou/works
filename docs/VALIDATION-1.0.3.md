# 1.0.3 BOSS 完整聊天页发送验证

日期：2026-09-14。环境：Windows x64、Python 3.11、PyInstaller 6.22.2。

## 问题与修复

用户截图显示文字已发送，但任务随后出现 `Timeout 8000ms exceeded`。原代码开启图片简历时，在文字小窗仍覆盖页面的情况下点击背景聊天入口；该点击位于图片发送的异常处理之外。另一个问题是图片发送只等待成功提示，而当前完整聊天页通过消息记录的送达状态确认结果。

本版按用户指定流程处理：

1. 点击目标职位“立即沟通”，优先识别直接打开的完整聊天页，也支持该入口打开的新标签页。
2. 对原生问候确认框，使用其“继续沟通”入口；旧版文字小窗先关闭后进入目标聊天页，不在小窗发送自定义文字。关闭失败时不点击被遮挡的背景按钮。
3. 在完整聊天页填写自定义招呼语，等待发送按钮移除 `.disabled` 后点击一次。
4. 确认本次新增的本人文字消息送达或已读，再发送已启用的图片简历。图片同样根据新增本人消息的送达 / 已读状态确认，不依赖成功提示。
5. 兼容多行文字渲染成 `<br>`；排除历史消息、对方图片、发送中状态及旧消息回执更换 ID。关闭职位页面失败不覆盖已确认的发送结果。

发送未确认时仍保留页面和待核实记录，不自动重投。文字已确认但图片未确认时，记录明确区分两者。

- [BOSS 完整聊天公开脚本](https://static.zhipin.com/fe-zhipin-geek/web/chat-new/v5543/static/js/chat.71252f3c.js)：聊天输入框、发送按钮的防抖启用、本人文字 / 图片记录及消息状态组件。
- 公开前端状态回调确认：送达事件更新消息状态，并可能把客户端消息 ID 替换成服务端 ID，因此新增 ID 本身不足以证明本次发送成功。

本地参考实现 `Boss.java` 也采用关闭文字小窗后进入完整聊天发送图片的顺序。没有把单纯点击或选择文件当作成功证据。
