# 工作无忧 · Python

参照 [loks666/get_jobs](https://github.com/loks666/get_jobs) 实现的本地求职助手：**FastAPI 后端 + SQLite + Playwright + 中文网页管理界面**。无需 Java、Node.js 构建或外部数据库。

## 启动

已构建时，可直接双击 `dist/Get-Jobs-Python-1.0.1.exe`，无需另装 Python。EXE 仍使用本机 Chrome/Edge；个人数据保存在 EXE 同级的 `data/` 目录，退出时关闭服务终端。此构建不包含个人数据或原始参考仓库。

Windows 双击 `start.bat`，首次自动创建虚拟环境并安装依赖，需要 Python 3.11+。已有环境可直接运行：

```powershell
.\.venv\Scripts\python.exe run.py
```

管理页面：<http://127.0.0.1:8765>，交互式接口文档：<http://127.0.0.1:8765/docs>。启动器默认打开管理页面；终端按 Ctrl+C 停止服务。

程序使用本机 Chrome，未安装时尝试 Edge，再尝试 Playwright Chromium。没有可用浏览器时运行：

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

1.0.1 修复 BOSS 刷新/重定向兼容问题：BOSS 单独使用 Patchright 1.62.3 和真实浏览器窗口尺寸；其他平台继续使用 Playwright。保留 `dist/data/` 即可沿用配置和已有登录资料。升级前关闭旧版后台和它打开的招聘浏览器，再启动新的 EXE。BOSS 缺少浏览器时也可运行 `python -m patchright install chromium`。

重复点击登录只会复用当前页面；验证中或加载中不会被强制跳走。检测到连续重定向、退回空白页时会停止任务并提示，不自动连续重试。平台验证码仍需手动完成。

端口被占用或希望换数据位置时：

```powershell
.\.venv\Scripts\python.exe run.py --port 8766 --data-dir D:\JobsData --no-browser
```

只监听本机回环地址。招聘网站需要本机浏览器扫码登录，此应用面向单用户桌面使用。

## 使用顺序

1. 在“平台配置”选择 BOSS 直聘、猎聘、前程无忧或智联招聘，设置岗位、城市、月薪、过滤条件、招呼语和投递间隔并保存。
2. 点击平台登录，在打开的浏览器里自行完成扫码；完成后刷新登录状态。各平台使用独立浏览器资料目录，关闭软件后可复用有效登录信息。
3. 如使用 AI，在“AI 与简历”配置服务地址、模型、API Key、个人经历、提示词和匹配分数。先保存，再用一段 JD 测试。随后在对应平台启用 AI 筛选。本地模型允许不填 Key。
4. 先运行“仅预览”：会真实搜索并读取职位、执行筛选、生成招呼语和保存记录，但不会申请职位或向招聘方发消息。
5. 检查“投递记录”中的匹配结果；确认配置后再选择真实投递。页面会明确提示将向招聘方发出申请或消息。
6. 随时停止任务。停止会等待当前页面操作收尾；已提交给平台的动作不会撤回。

## 功能对应

| 功能 | 本实现 |
| --- | --- |
| 四平台接入 | 独立登录、搜索地址、职位读取、分页和投递操作 |
| 搜索条件 | 多关键词、多城市、目标月薪、排除词；高级查询参数扩展平台筛选 |
| HR 与猎头筛选 | 活跃状态、猎头标记；平台未提供相应信息时不臆测 |
| AI 匹配 | OpenAI 兼容接口，个人经历 + JD，评分/原因/个性化招呼语；模型异常停止任务 |
| BOSS 招呼语 | 自定义模板，支持 `{title}` 和 `{company}`；开启 AI 时使用生成结果 |
| BOSS 图片简历 | PNG/JPEG 图片上传、保存和浏览器发送流程 |
| 黑名单 | 按公司名称匹配，可限定平台；记录中一键加入；BOSS 最近拒绝会话同步 |
| 持久登录 | 四平台独立持久化浏览器资料；退出登录删除对应平台本地资料 |
| 记录与分析 | SQLite 持久化、状态/平台/关键词筛选、分页、CSV、近七日趋势 |
| 运行管理 | 单任务运行、停止、每日次数上限、间隔控制、日志和 SSE |
| 企业微信通知 | 任务结束向配置的机器人发送统计，失败写日志 |

内置北京、上海、广州、深圳、杭州、成都、南京、武汉、苏州、重庆、天津、西安的四平台城市码。其他城市请在高级设置填写对应平台的城市码，数量和城市一一对应；不支持的城市不会自动扩大成全国搜索。

平台高级查询参数是 JSON 字典，例如 BOSS 的 `experience`、`degree`、`industry`、`scale`、`stage`、`salary`、`jobType`。应使用该平台当前筛选 URL 中的值；不同平台的城市码、薪资码不能混用。关键词和城市参数由上方专用字段控制。

## 记录含义和核实边界

- **仅预览**：筛选通过但未投递。预览数据来自真实搜索；应用首次启动没有示例职位或虚构统计。
- **已投递**：操作后观察到平台成功提示、目标按钮变为已申请，或 BOSS 新增招呼消息；不代表 HR 已读或回复。
- **已过滤 / 已沟通**：命中过滤条件，或平台显示此前已申请。
- **待核实**：点击后未得到明确结果。任务会停止，该职位进入持久化去重记录，不会自动重投；请在招聘网站核实。
- **失败**：配置、AI、登录或页面操作出现明确错误。若发生过投递尝试，同样保留去重记录。

每日投递上限按本机当天的投递尝试计数，包含失败和待核实，重启程序不会清零；平台可能还有自己的次数限制。月薪按区间相交筛选；年薪 /12、日薪 ×21.75，13/14 薪不额外折算到月薪。面议或未知薪资默认放行。

四个平台的页面结构与风控会变化。原项目 README 本身也记录了 BOSS 与智联的问题。本版本提供实际浏览器适配代码，但本次开发未使用你的招聘账号、未向 HR 投递、未真实调用收费模型或机器人；本地测试通过不能代替账号登录后的平台验收。遇到验证码请手动完成；页面结构变化会明确报错，不自动绕过验证。AI 生成的招呼语实际发送仅在 BOSS 使用，其他平台遵循自己的申请或招呼机制。

## 本地数据

`data/jobs.sqlite3` 保存配置、记录、黑名单、日志和任务；`data/profiles/` 保存平台登录资料，`data/resume/` 保存图片简历。不要提交或分享这些目录。

Windows 上 AI Key 和企业微信 webhook 使用当前用户的 DPAPI 加密，接口不会回传原文；非 Windows 环境依赖仅文件所有者可访问的目录权限。个人经历和职位记录保存在本地数据库。启用 AI 后会向你配置的模型服务发送个人经历及 JD。密钥字段留空保存表示保留原值，勾选清除才删除。数据库、登录资料和简历默认排除在 Git 和打包之外。

## 开发与验证

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

测试通过临时数据库、模拟模型响应、模拟浏览器以及本地 HTML 夹具验证逻辑，不对外发送申请。浏览器夹具测试需要可用的 Chrome/Edge/Chromium；具体跳过项会在 pytest 报告显示。

主要文件：`jobs_app/main.py`（HTTP 接口）、`engine.py`（任务与去重）、`browser.py`（四平台适配）、`matching.py`（筛选、AI、通知）、`storage.py`（本地持久化）、`static/`（管理界面）。

Windows 构建 EXE：`powershell -ExecutionPolicy Bypass -File .\build.ps1`，输出 `dist/Get-Jobs-Python-1.0.1.exe`。
